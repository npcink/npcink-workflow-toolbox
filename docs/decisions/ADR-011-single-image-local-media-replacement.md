# ADR-011: Single-Image Local Media Replacement

Status: accepted.

## Context

One operator opening **Optimize this image** from the Media Library is already
present, acts on one known attachment, sees the exact generated bytes, and can
receive a restorable backup. Requiring a separate Core proposal for that same
present-person decision adds ceremony without improving the decision evidence.
Batch, background, delegated, and external-client replacement do not share
those conditions.

## Decision

Classify one exact Media Library replacement as `strong_local_confirmation`
when all of these remain true:

- source is the WordPress admin UI and the actor is a present click;
- scope is exactly one image attachment;
- the same-origin artifact preview loaded and its artifact id is confirmed;
- the final action is explicitly confirmed as `replace_current`;
- Toolkit dry-run validation succeeds;
- Toolkit creates backup, repair, rollback, and verification evidence.

Toolbox exposes `POST /strong-local-confirmation/media-derivative`. During that
request only, it authorizes exactly
`npcink-abilities-toolkit/adopt-cloud-media-derivative`, invokes the Toolkit
callback, and removes the filter in `finally`. Toolbox does not duplicate file,
metadata, reference-repair, or rollback implementation.

## Consequences and Stops

The single-image UI says **Apply to Media Library** and creates no Core
proposal. Zero/multiple selections and every batch workflow remain
Core-governed. The exception does not permit save-as-new, background execution,
external Agent execution, queues, retries, approval storage, provider control,
or authorization of another Toolkit write ability.

The route fails closed on unknown fields, mismatched actions, unverified
preview state, artifact mismatch, non-image attachment, missing capabilities,
classifier drift, Toolkit dry-run failure, or artifact delivery failure.
