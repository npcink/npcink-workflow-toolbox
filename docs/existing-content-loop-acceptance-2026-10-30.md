# 现有内容辅助链路验收与后续处置（2026-10-30）

状态：Local WordPress + M4 的开发验收；不是生产发布、代表性准确率或自然使用证明。

## 真实入口与职责

摘要、标题和选中文本改写的实际入口属于已启用的 WordPress AI 插件：

`WordPress AI Ability → Cloud Addon → Cloud WordPress operation → 建议预览 → 作者采用 → 原生保存`

- 摘要：文章设置里的生成文章摘要。
- 标题：标题工具栏的标题建议、插入与重新生成。
- 改写：选中段落后的“调整内容长度 → 改写”，先展示原文/建议对照，再接受。
- Toolbox 自己的段落功能仍是审阅；独立标题、摘要 intent 已退役，见
  [编辑器意图收口](editor-intent-convergence-decision.md)。此次没有恢复旧入口。

当前文章或所选段落是这些操作的实际输入。它们不要求新增文档上传、问答入口或
另建资料库。本次没有证明每个操作都注入了额外 Site Knowledge 背景。
Cloud Addon 负责连接器投影与传输，Cloud 负责模型执行，本地作者仍负责采用与保存。

### 图片遗留问题

像素向量检索与图像理解分别验收，不能互相代替。
[已有实测](site-content-answer-v1.md#separate-image-acceptance-and-limits)
证明两张真实图片的像素检索及单图理解可用；本地 2B 路由的双图和山谷原大图
超过现有 30 秒交互预算。源码核对确认 Addon 的该路径固定为 inline、30 秒、
零重试、无 fallback；Cloud 当前输出上限为 1,400 tokens。单图成功不能推出
大图或多图服务已满足交互要求。

处置：保持已验收的单图及现有预览图路径；不提高超时、不增加本地拆批队列，
不切换生产 Provider。后续真实多图需求由 Cloud 的路由/容量负责人用相同图片
和固定预算验收合适模型；只有结果、延迟和失败路径均通过才扩展可用范围。

69 张历史图片在恢复站点缺少原图和已登记变体；本次站点目录也未找到可用归档包。
继续标记 metadata-only，恢复依赖另外提供的原文件备份。没有原文件时不能重新
生成像素向量，也不能用相同维度或文字嵌入宣称像素覆盖。该外部依赖仍未解除。

## 后续维护经验

1. 先确认入口、调用方和当前允许的任务，避免把通用内容能力误写成新问答/上传需求。
2. 生成、审阅、编辑状态采用、原生保存、数据库回读分别取证；预览成功不能证明落库。
3. 失败 fixture 标明注入层；模型真实重试和后台故障演练是不同证据。
4. 缺原图、模型容量不足、产品尚无需求、人工未接受分别记账，不用新增框架掩盖。
5. 聊天归档、提交保全、PR 合并、开发运行、人工接受和生产发布分别报告。
