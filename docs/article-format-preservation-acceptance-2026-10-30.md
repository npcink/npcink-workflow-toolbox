Date: 2026-10-30. Module: Toolbox editor formatting / existing publish preflight.
Source base: `70b4907a` (merged #344). Implementation file hashes and sample
fingerprints are in the [body-free receipt](article-format-preservation-evidence-2026-10-30.json).
This is developer acceptance, not a release, deployment or independent author
acceptance. No Cloud, Addon, Toolkit or OSS source/runtime was changed.

## Preservation and author correction

Formatting may only make bounded paragraph/list/BR layout changes and insert
one CJK/Latin-or-digit boundary space. Words, digits, symbols, punctuation,
links, multimedia and protected blocks cannot be corrected or rewritten.
PHP and browser validation reject mutations. A quick edit followed by Undo
during a request also invalidates the result.

Existing publish preflight now shows local punctuation hints, actual bounded
coverage and unique-evidence navigation. Navigation selects an existing block;
it does not edit. Changed drafts mark findings stale and disable navigation.
All text and punctuation corrections belong to the author. Generic grammar,
general cross-paragraph logic, body-risk classification and fact verification
remain unimplemented, as the report explicitly discloses.

## Evidence

Real WordPress tokenizer smoke passed preservation and adversarial mutation
cases for words, numbers, punctuation, links, audio/video/embed/image/gallery
and custom blocks. A schema-default compatibility fix allows unchanged
third-party defaults such as paragraph `aiResized=false`; non-default
attributes remain protected and native serialization must still match.

The headless browser used `https://magick-ai.local`, task assets/translations,
and the site's existing signed Cloud formatting transport. It verified visible
rich-paragraph formatting, protected table/code and block IDs, idempotence,
native Undo/Redo, one-shot Undo, delayed response rejection, Cloud failure
preservation and a 390px viewport. Task PHP was separately loaded through a
CLI bootstrap with the mounted Toolbox skipped; the browser report fixture
was generated by that PHP and intercepted only `publish_preflight`. It proved
punctuation hints, coverage disclosure, navigation without edits and stale
navigation disabling. It is not new-source production REST deployment or
Cloud language-analysis evidence.

No post-write requests or page errors occurred. Two native Gutenberg user
preference write attempts were blocked by the harness; none was allowed.
Disposable draft 282992 and its temporary login session were deleted. Earlier
failed harness runs also cleaned up their named drafts/sessions; an initial
orphan session was removed by its exact verifier, preserving other sessions.
The existing site plugin mount was restored and later runs used asset/CLI
overrides without changing it. Desktop/mobile/report screenshots remain ignored
local artifacts under `build/smoke/` and were visually inspected.

The twelve public saved articles were sent through the actual signed Cloud
formatting transport and independent task PHP validation. Results: seven
`PARTIAL`, one `UNCHANGED`, two unchanged `REVIEW`, two `BLOCKED`. All twelve
saved originals remained byte-identical. This establishes preservation, not a
12/12 usable formatting rate. The first corpus run stopped at a refusal; the
completed run explicitly recorded refusals and continued through all samples.

Both refusals reproduce with the base branch validator. Article 280942 contains
unsupported/unbalanced inline structures, so its structure projection fails.
Article 280861's candidate changes protected blocks by inserting spaces and is
rejected. Keep both fail-closed; compatibility needs a separate Cloud/validator
contract and regression before supporting these cases.
