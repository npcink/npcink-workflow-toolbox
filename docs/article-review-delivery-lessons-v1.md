# Article Review Delivery Rules and Lessons v1

Status: active for Toolbox formatting and read-only review work, updated 2026-11-01.
These rules refine the existing boundary and development workflow; they do not
authorize new checks, writes, infrastructure or product releases.

## 工作审视报告

### 原定目标与完成情况

- [x] 排版只调整允许的布局/边界空格，保留原文、标点、符号、链接及多媒体。
- [x] 中文语句检查只给可核对的原句、疑点、方向与定位，作者自行修改。
- [x] 原样快照、严格 schema、偏移复核、过期保护、脱密证据和真实安装验收。
- [x] 两个排版兼容案例已修复；中文扩大评估保留原始误报和标签错误。
- [x] 有界逻辑/成人内容语境提示已合入并通过真实安装验收，见
  [2026-11-01 验收](article-review-context-acceptance-2026-11-01.md)。24 例首轮
  保留 1 例超时，不把不可用算作零提示通过。
- [ ] 通用准确率、独立作者反馈、未覆盖的内容风险类别、真实 OSS 写入/备份/恢复及生产发布。
  成人语境提示不能代表全面内容安全检查。

### 已验证的做法

保留只读提示与定位，遇到不兼容或引用不可信时拒绝；同时验证有用正例和
正常/有意标点的零提示反例。真实保存源保持不变，不用“全部放行”冒充兼容。
失败、覆盖缺口和未检查类别都可见，未通过的阶段不被成功截图覆盖。

## 后续实施规则

1. **先定所有者和边界。** Toolbox 采集/校验/展示，Addon 签名传输，Cloud
   管分析与模型，作者判断修改。复用 `publish_preflight` 和 `/v1/runtime/execute`；
   不增加平行注册表、写接口、版本号硬拒或自动发布阻断。
2. **原文是待检查的数据。** 不执行正文指令；不返回更正文或可执行替换字段。
   排版只做契约允许的布局/空格变化，任何词句、数字、符号、标点、链接或媒体
   变化都拒绝。保持代码、自定义块和媒体保护，不为提高成功率放宽验证。
3. **坐标与身份必须可复核。** 统一 Unicode JSON/hash；原样保留空白、换行及
   U+2028/2029。JS 使用 UTF-16 code units，不能用 Python 字符数或 PHP 字节数
   充当同一偏移。客户端 id 只作导航线索；先复核完整引文范围，再判断唯一位置。
4. **用编辑代次保护新鲜度。** 文本相等、撤销到旧文、同文换块不复活旧报告。
   运行途中编辑也让返回报告失效。编辑器订阅比较不可变状态引用，不在热路径
   反复序列化全文；明确显示可读但不可定位的状态。
5. **结果只代表实际覆盖。** 区分完成、部分、拒绝、不可用、上限和未检查；
   展示排除/截断数量。零提示不证明文章正确。逻辑/风险需另立契约和评估，
   不能从旧设计示例直接启用。正常医学/教育/新闻/文学语境需有反例保护。
6. **验证证据分层。** 先窄行为/契约，再确定性门禁，再按需要运行有上限的真实
   模型/安装验收。离线桥接只证明交互，CLI 只证明所测链路；安装验收必须使用
   真正 enqueued 资源及真实 REST 输出。真实模型不为凑结果盲目重复；诊断清楚
   的网络恢复后重查也要保留前次失败及 run_id。
7. **隐私约束覆盖成功与失败。** 正文 no-store；核对输入、ciphertext、结果和
   最终错误出口。结果为 null 与显式 omitted marker 是不同观测，分别记录。
   Git 只留脱密计数/布尔值/版本/run_id；本地原始材料私有归档。上游保留政策
   未查就明确未知，不能从 Cloud no-store 推导 provider 零保留。
8. **源代码与运行环境分别验收。** 已提交、已推送、PR 合入、运行候选、干净
   master 晋升、生产部署互不等同。精确 SHA 和 squash merge 用 tree 比较；
   M4 回执记录 dirty/bundle，不仅记录 HEAD。绝不抢锁、部署或重置其他会话环境。
9. **真实安装必须有稳定来源。** 活跃插件不能指向要清理的临时 worktree。
   先核对并保留现有本地补丁、MU 文件及设置指纹；组合版本明确标为本地例外，
   不悄悄覆盖或宣称已合并。不要为此扩展供应商、模型、队列或审批所有权。
10. **收尾要能独立恢复。** 先核对 PR 状态、精确 head、工作区和安装引用，
    再清理已合入分支/worktree；远端删除带期望 SHA 保护。保留恢复 refs 和
    被忽略的验收材料。主工作区受应用保护时保留并说明，不绕过保护；其他
    会话、安装源码、本地未合并补丁都列明所有者和用途。

## 本轮新增经验（2026-11-01）

- 严格成对引文能核对坐标与分析范围，不能证明模型推断正确；语义实用性需单独审阅。
- 模型“完成”只是声明本次有界分析完成。部分、拒绝和不可用不能折算成成功；
  初始 24 例的新闻超时必须保留，即使以后传输修复通过也不能回填为质量通过。
- 模型执行期限与 HTTP 接收期限需要错开。实测 30 秒/30 秒会丢失超时回执和
  run_id；文章审阅接收余量改为 40 秒，模型仍 30 秒、零重试、无 fallback。
- PHP 行号移动也会改变 POT 源引用。提交前按需要运行 i18n:check；本轮 CI 首次
  发现 POT 陈旧，已保留失败并刷新引用，不以重跑掩盖缺少文件的提交。
- 冻结标签、初始结果、后续诊断分别记账；审阅器的假设性建议必须核对真实 guard，
  不为消除意见而放宽隐私、证据或检查选择规则。
